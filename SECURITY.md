# Security policy

## Supported versions

Security fixes are applied to the latest release on the main branch.

## Reporting a vulnerability

Do not open a public issue for a vulnerability that could enable relay abuse, credential theft, mailbox disclosure, or remote code execution. Contact the repository owner privately through the security contact published on the GitHub profile. Include:

- affected file and version;
- reproduction steps using synthetic data;
- impact and prerequisites;
- suggested mitigation, if known.

Do not include real credentials, private keys, email content, access tokens, or customer information.

## Scope

This repository contains guidance and read-only diagnostics. Vulnerabilities in upstream software must also be reported to the relevant upstream security team. Misconfiguration of a deployment is operationally important but is not necessarily a vulnerability in this repository.

## Response targets

The project aims to acknowledge a valid private report within five business days, establish severity, prepare a coordinated fix, and publish credit when requested.
